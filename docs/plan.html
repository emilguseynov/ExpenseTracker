Поля расхода

  • id — BIGINT GENERATED ALWAYS AS IDENTITY

Шаги

Один шаг за раз. Следующий начинается, когда проверка текущего совпала с ожиданием. Файлы заранее пустыми не создавай: каждый появляется в своём шаге.

1

PostgreSQL без Go

База, миграция и запросы

Сначала докажи данные в psql. Пока числа не сходятся здесь, ошибку SQL легко принять за ошибку Go.

Создай две базы: expense_tracker для ручной работы и expense_tracker_test для будущих тестов. Миграцию на этом шаге примени только к первой. Вторая пригодится на шаге 3, тесты накатят тот же файл сами.

Сделать

  1. createdb expense_tracker и createdb expense_tracker_test.
  2. Файл migrations/001_create_expenses.sql: таблица expenses с полями из рамок.
  3. psql -d expense_tracker -f migrations/001_create_expenses.sql.
  4. Вставь четыре сентябрьские строки. Даты задай явно, в центах: 5000, 2000, 10000, 3000.
  5. Добавь пятую: 2026-10-05, food, 1000 центов.

Запросы, которые должны сойтись

  1. Все строки — 5 штук.
  2. category = 'food' — три строки, 90 евро.
  3. Сентябрь полуинтервалом — четыре строки, 200 евро. Расход 30 сентября днём входит, 5 октября нет.
  4. SELECT category, SUM(amount_cents) … GROUP BY category по всем строкам: food 9000, transport 2000, electronics 10000.
  5. Тот же GROUP BY с условием сентября: food 8000, transport 2000, electronics 10000.

Границы сентября запиши так, как потом напишешь их в Go: created_at >= '2026-09-01' и created_at < '2026-10-01'. Сравнение <= '2026-09-30' оставляет за бортом время после полуночи этой даты.

На проверку

Вывод пяти запросов из psql. Отдельно: сумма групп за сентябрь равна 20000 центам.

2

Go · соединение

Пул и ping

go mod init expense-tracker. Зависимость — модуль pgx/v5. В internal/database/postgres.go открой пул из DATABASE_URL и сделай ping с таймаутом через context. main логирует результат через log/slog и выходит. Маршрутов ещё нет.

Готово, когда

  • При живой базе процесс пишет успешный ping и завершается.
  • При остановленном PostgreSQL процесс завершается с ошибкой, а не зависает.
  • Строка подключения не зашита в код, она приходит из DATABASE_URL.

На проверку

Два запуска: с работающей базой и без неё. Текст обеих записей лога.

3

Репозиторий · чтение

Список, запись по id и первый тест

В модели держи доменные поля. Сумма внутри Go — int64 центов. Рядом одна функция перевода центов в строку "50.00", её потом возьмут и JSON, и статистика.

Методы репозитория принимают context.Context первым аргументом. Нужны список всех и чтение по id. Чужой id — это твоя ошибка «не найдено», её источник в pgx — pgx.ErrNoRows. Сбой соединения должен остаться другой ошибкой: позже они станут 404 и 500.

Общий помощник тестов живёт в _test.go этого пакета. Он читает TEST_DATABASE_URL, без переменной делает t.Skip, выполняет migrations/001_create_expenses.sql и перед каждым тестом очищает expenses, сбрасывая счётчик id. Тесты ходят только в expense_tracker_test.

Тест этого шага

  • Вставь четыре сентябрьские строки через репозиторий или SQL помощника.
  • Список возвращает их, суммы сходятся с центами.
  • Несуществующий id даёт «не найдено».
  • Ошибочный адрес базы даёт иную ошибку, не «не найдено». Это можно проверить отдельным коротким вызовом с битым URL, без падения всего набора.

На проверку

go test -v ./internal/expense и кусок репозитория, где ErrNoRows превращается в твою ошибку.

4

HTTP · чтение

Список и один расход

Появляется хендлер. Сервис пока тонкий: принимает запрос и зовёт репозиторий. Правила суммы и категории подождут шага 5. Маршруты стандартного мультиплексора Go 1.22: метод входит в шаблон пути.

main больше не выходит после ping. Он слушает HTTP_ADDR, по умолчанию разумный локальный адрес вроде :8080, если переменная пустая.

Ответы

  • GET /expenses — 200 и JSON-массив.
  • Пустая таблица — []. Для этого в хендлер уходит пустой слайс, а не nil.
  • GET /expenses/1 — объект с amount как "50.00", время в RFC3339.
  • Несуществующий id — 404.
  • GET /expenses/abc — 400.

Две проверки

  • curl против expense_tracker, сверка одного объекта с psql.
  • httptest против тестовой базы через тот же путь, что у сервера: хендлер, сервис, репозиторий. Минимум два случая — пустой список и 404.

Фейковый репозиторий не заводи. Тест HTTP уже видит настоящий SQL.

5

Запись

Создание, удаление и разбор суммы

POST принимает amount, category, description. Поле created_at от клиента не используется, его ставит база значением по умолчанию.

Правила сервиса, до репозитория

  • "50.00" → 5000. Ноль, минус и больше двух знаков после запятой — ошибка для 400.
  • Категория без краевых пробелов и в нижнем регистре. Пустая после обрезки — ошибка.
  • Пустое описание сохраняется как NULL, в JSON поле тогда отсутствует.

Тесты

  • Без базы: таблица входов разбора суммы, включая "50.10", "50.1", "0", "-1.00".
  • С базой через httptest: POST даёт 201, GET читает ту же строку, DELETE даёт 204, повторный DELETE и следующий GET дают 404.
6

SQL · условия

Фильтры списка

Список принимает структуру фильтра: категория, начало дня from, начало дня после to. Оба конца необязательны. Если заданы оба и from позже to — 400. Категория в запросе тоже приводится к нижнему регистру, поэтому Food находит food.

Сначала напиши два отдельных запроса и подключи их по отдельности: только категория и только период. Когда оба верны, собери один метод. В текст SQL попадают куски условий и номера $1, $2, $3. Значение категории и даты в строку запроса не подставляется.

Тесты на данных шага 1

  • ?category=food — три строки, 90.00 в сумме.
  • ?from=2026-09-01&to=2026-09-30 — четыре строки, без 5 октября.
  • Оба фильтра вместе — две сентябрьские food, 80.00.
  • from=2026-13-01 и диапазон, где начало позже конца, — 400.
7

Агрегация

Статистика, которая сходится со списком

Один запрос: SELECT category, SUM(amount_cents) FROM expenses GROUP BY category. Общий total сложи в Go из полученных групп. Категорий без строк в объекте нет. Суммы в JSON — строки с двумя знаками, как у расхода.

Вторым движением повесь на /stats те же category, from и to. Условие WHERE общее со списком, его стоит собрать один раз, чтобы границы периода не разъехались.

Форма ответа за сентябрь

total = "200.00". В by_category: food "80.00", transport "20.00", electronics "100.00".

8

Граница входа

Ошибки, которые отвечают, а не роняют процесс

Декодируй JSON так, чтобы неизвестное поле давало 400. Битый JSON, сумма "0.00" и пустая категория тоже 400, с коротким сообщением без внутренностей драйвера. Ошибка соединения, если дойдёшь до неё отдельной проверкой, остаётся 500 и тоже без текста SQL.

Случаи httptest

  • Тело не JSON.
  • Лишнее поле рядом с правильными.
  • "amount": "0.00".
  • "category": " ".
  • Успешный POST по-прежнему 201: жёсткий разбор не сломал обычный путь.

Шаг закрывает v1

После него сервис умеет записать расход, отфильтровать список, посчитать статистику и объяснить клиенту ошибку ввода. Индексы, остановка по сигналу, PATCH и пагинация сюда не входят.

Готово

Пять запросов шага 1 в psql дают оговорённые центы.
go test ./... проходит при заданном TEST_DATABASE_URL и пропускается без него.
curl создаёт расход, читает его, фильтрует сентябрь и удаляет.
За один и тот же фильтр сумма списка, сумма групп и total равны.
Чужой id — 404, плохой ввод — 400, текст SQL в ответе не появляется.

На границу шага приноси: что ожидал, что показал psql или тест, и свой кусок, который это делает. Разбираем твоё решение.
